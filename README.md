# lensa-signal-bot

لایه‌ی عملیاتی تلگرام برای Lensa روی Cloudflare Workers + D1 + Workflows؛ شامل تحلیل، فیت و انتخاب استراتژی، سیگنال، مدیریت ریسک و پیگیری خودکار.

## چیکار می‌کنه

1. تمام جریان‌های اصلی از منوی دکمه‌ای اجرا می‌شوند؛ پیام ویزارد در هر مرحله ویرایش می‌شود تا چت شلوغ نشود.
2. کاربر Spot/Futures، جهت، لورج اختیاری، تایم‌فریم، تعداد روز، کارمزد، زمان Fill، روش حدها و تنظیمات حجم را مشخص می‌کند.
3. برای همان نماد، تایم‌فریم و تعداد کندل، دسترسی KuCoin و Bitget به‌صورت زنده بررسی می‌شود؛ فقط صرافی‌هایی که حداقل ۹۰٪ پوشش معتبر دارند دکمه‌ی انتخاب می‌گیرند و انتخاب کاربر در فیت و صدور سیگنال حفظ می‌شود.
4. Workflow همه‌ی ۲۰ استراتژی را پارامتری فیت می‌کند، Walk-Forward می‌گیرد و آمار کامل هرکدام را در چند پیام خوانا نشان می‌دهد.
5. کاربر معیار رتبه‌بندی (بازده، Sharpe، نرخ برد، افت یا Profit Factor) و سپس خود استراتژی را انتخاب می‌کند؛ انتخاب خودکار و پنهانی وجود ندارد.
6. وضعیت زنده‌ی همان استراتژی بررسی می‌شود و فقط در Long/Short بودن، سیگنال با جزئیات کامل صادر می‌شود؛ Flat شفاف اعلام می‌شود.
7. SL/TP در Futures بر اساس ROI پوزیشن به حرکت قیمت تبدیل می‌شوند؛ مثلاً SL ده درصد با 10x یعنی تقریباً یک درصد حرکت قیمت. حجم هم به سقف واقعی حساب × لورج محدود می‌شود.
8. کنترل کیفیت کندل، بازار، Decision Center، Forecast، Backtest، ابزارهای ریسک، Watchlist، اسکن، هشدار قیمت، ژورنال و تاریخچه در ربات در دسترس‌اند.
9. تمام ویزاردهای چندمرحله‌ای دکمه‌ی «مرحله قبل» دارند تا کاربر بدون لغو فرم انتخاب قبلی را عوض کند.
10. هر ۱۰ دقیقه Cron هم سیگنال‌های باز و هم هشدارهای عبور قیمت را بررسی و نتیجه را به کاربر اعلام می‌کند.
11. پنل ادمین کاملاً دکمه‌ای است؛ فقط `OWNER_TELEGRAM_ID` می‌تواند ادمین اضافه/حذف کند و افزودن دستی آیدی حتی وقتی هنوز کاربر شناخته‌شده‌ای وجود ندارد کار می‌کند.

سیستم ادمین و پلن هم از فاز ۱ سرجاشه (پلن‌ها فقط *مصرف* رو محدود می‌کنن، نه کیفیت تحلیل رو).

## فرض طراحی

بات برای چت خصوصی (هر کاربر با بات، یک‌به‌یک) طراحی شده، نه گروه — rate limit و ردیابی سیگنال‌ها بر اساس user id هستن.

## راه‌اندازی (دیپلوی از صفر)

```bash
npm install
```

**۱. دیتابیس D1:**
```bash
npx wrangler d1 create lensa-signal-bot-db
```
`database_id` برگشتی رو توی `wrangler.toml` جای `REPLACE_WITH_D1_DATABASE_ID` بذار.

**۲. اجرای schema:**
```bash
npm run db:migrate:remote
```
Worker و Workflow در شروع، جدول‌های عملیاتی افزوده‌شده و ستون `backtest_detail_json` را هم به‌شکل idempotent در D1 بررسی و در صورت نبودن ایجاد می‌کنند. بنابراین خطای نسخه‌های قدیمی مثل `no such table: signal_fit_runs` بعد از دیپلوی جدید خودکار ترمیم می‌شود. اجرای `npm run db:migrate:remote` همچنان روش استاندارد و پیشنهادی برای همگام‌سازی کامل schema است.

**۳. بات تلگرام:** با [@BotFather](https://t.me/BotFather) بسازش و توکن رو بگیر.

**۴. آیدی عددیت:** از [@userinfobot](https://t.me/userinfobot) — جای `REPLACE_WITH_YOUR_TELEGRAM_USER_ID` (`OWNER_TELEGRAM_ID`) توی `wrangler.toml` بذار. اولین پیامت به بات، خودکار ادمینت می‌کنه.

**۵. secretها:**
```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET   # یه رشته‌ی رندوم، مثلاً: openssl rand -hex 24
```

**۶. دیپلوی:**
```bash
npm run deploy
```

فیت پارامتری همه‌ی استراتژی‌ها، به‌خصوص استراتژی Monte Carlo، از سقف CPU ده میلی‌ثانیه‌ای Workers Free بیشتر است. برای اجرای قابل‌اعتماد این نسخه از Workers Paid استفاده کن (پیش‌فرض هر invocation برابر ۳۰ ثانیه است).

**۷. ثبت webhook** (یه بار):
```bash
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://lensa-signal-bot.<subdomain>.workers.dev", "secret_token": "<TELEGRAM_WEBHOOK_SECRET>"}'
```

**۸. تست:** `/start` بزن (ادمین می‌شی) و از منوی دکمه‌ای «سیگنال جدید» رو انتخاب کن.

## تست

```bash
npm test
```
تست‌ها schema، D1، امنیت دسترسی، پلن و ادمین، زنجیره‌ی داده، کیفیت کندل، منو و ویزارد، محاسبه‌ی لورج و حجم، هشدارها، تشخیص TP/SL و Workflow فیت‌و‌تصمیم را پوشش می‌دهند.

## منبع داده‌ی بازار

KuCoin و Bitget مسیرهای صرافی با OHLCV واقعی و صفحه‌بندی برای بازه‌های طولانی‌اند. پیش از سیگنال یا تحلیل، هر دو مسیر برای درخواست دقیق کاربر probe می‌شوند و فقط منبعی نشان داده می‌شود که داده‌ی سالم و حداقل ۹۰٪ پوشش بازه را برگرداند. بعد از انتخاب، فیت بدون fallback پنهانی روی همان صرافی انجام می‌شود. CoinGecko صرفاً fallback داخلی قیمت/جریان‌های قدیمی است و چون صرافی نیست در انتخاب منبع نمایش داده نمی‌شود. ترتیب زمانی، OHLC، شکاف‌ها و تازگی داده نیز پیش از تحلیل اعتبارسنجی می‌شوند.

## معماری Cloudflare

تمام اجرای برنامه و نگهداری state روی Cloudflare است: webhook و API ربات در Worker، فیت طولانی در Workflows، داده‌های کاربر/فرم/سیگنال/فیت/اتوماسیون در D1 و پایش‌ها در Cron Trigger. هیچ دیتابیس یا سرور اپلیکیشن خارجی در runtime وجود ندارد؛ API صرافی‌ها فقط برای خواندن دیتای عمومی بازار فراخوانی می‌شوند. SQLite داخل پوشه‌ی `test` فقط shim حافظه‌ای تست‌های محلی D1 است و در production استفاده نمی‌شود.
